## Findings considered and rejected

- (Round 3) "Builder button and image links accept `javascript:` URLs": not worth fixing. HTML blocks and the HTML editor can already hold any markup, every in-app preview is sandboxed, and mail clients strip these links.

- (Round 2) "Imports resubscribe unsubscribed contacts": imports only ever unsubscribe (`ColumnMapping.php:72`).
- (Round 2) "`UpdateContact` falls back to Subscribed": unreachable, because `ContactRequest` requires `status`.
- (Round 2) "Builder opens HTML emails instead of the HTML editor": by design. Drag and drop is the default editor. Only the `<head>` loss is a bug (010).

- PHPStan "undefined method `active()`" at `CampaignAudience.php:65` and "`Tag|Collection`" at `TagController.php:74`: type-inference false positives, not runtime bugs (the scope exists via `#[Scope]`; `findOrFail` gets a validated int). They are still fixed in 001 as type work.
- Cross-workspace data access: verified safe. The workspace scope fails closed, every `exists`/`unique` rule is workspace-scoped, and jobs use `runAs`.
- Tracking and unsubscribe links: HMAC-signed with `hash_equals`; clicks only redirect to stored links of the same campaign (not an open redirect).
- Email asset uploads: raster `mimes` only (no SVG), with hashed names.
- The hard-coded test `APP_KEY` in `packages/core/phpunit.xml`: the standard Testbench setup, test-only.
- Core importing host code: none found. Every `@/` import in core is on the agreed contract list, and there are no `App\` references besides the overridable `user_model` default.
