# Deploying Nudge

A practical checklist for running a self-hosted install in production.

## Requirements

- PHP 8.4 (Composer allows 8.3 and up), with the usual Laravel extensions.
- MySQL 8.4.
- Redis, for the queue and cache.
- Node, to build the frontend assets. It isn't needed at runtime.
- A long-running queue worker and the scheduler (see [Workers and scheduler](#workers-and-scheduler)).

## Install

```sh
composer install --no-dev --optimize-autoloader
npm ci && npm run build
cp .env.example .env
php artisan key:generate
php artisan migrate --force
php artisan storage:link
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

`storage:link` is needed once: images uploaded in the email builder are served from the `public` disk, and inboxes load them directly.

## First run

A new install has no accounts, and the first one becomes its owner. So that nobody who finds the site can claim it first, the first account can't be created on the website without a setup token. Use one of these:

- **From the server (recommended):** run `php artisan app:create-owner you@example.com --name="Your Name"`. It asks for a password, creates the account already verified, and refuses if any account exists.
- **In the browser:** set `SETUP_TOKEN` in `.env` to a long random value (for example the output of `openssl rand -hex 32`), and run `php artisan config:cache`. Then open `/register` and enter that token alongside your details. Remove `SETUP_TOKEN` and cache the config again afterwards.

Once the owner exists, `REGISTRATION_MODE` decides who else can sign up, and the setup token no longer matters.

## Environment values that must be set

`.env.example` ships production-safe defaults (`APP_ENV=production`, `APP_DEBUG=false`, secure and encrypted sessions). Never deploy with `APP_ENV=local` or `APP_DEBUG=true`: debug pages show request data and SQL to anyone.

- **App:** `APP_NAME`, `APP_URL` (the public `https://` address) and `APP_KEY` (generated by `key:generate`).
- **Database:** `DB_CONNECTION=mysql`, plus `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME` and `DB_PASSWORD`.
- **Redis:** `REDIS_HOST`, `REDIS_PASSWORD` and `REDIS_PORT`. Set `CACHE_STORE=redis` if you want the cache there too.
- **Queue:** `QUEUE_CONNECTION=redis`. The connection's `retry_after` must exceed the longest job timeout (imports run for up to an hour). The default is 3660 seconds (`REDIS_QUEUE_RETRY_AFTER`). Don't lower it, or long jobs get handed to a second worker while they're still running.
- **Mail:** set a real `MAIL_MAILER` (for example `smtp`) with its credentials, plus `MAIL_FROM_ADDRESS`. The default, `log`, writes password-reset and invitation links to the log file. This mailer only sends account email. Campaigns go through the sending providers configured in the app.
- **Tracking:** `MARKETING_TRACKING_URL`, only if tracking links and the unsubscribe page should be served from another domain.
- **Registration:** `REGISTRATION_MODE` is `invite` (the default: only email addresses with a pending workspace invitation), `closed` or `open`. The first account is created separately (see [First run](#first-run)).
- **Shared installs:** set `MARKETING_ALLOW_PRIVATE_SMTP_HOSTS=false` so workspace owners can't point SMTP at internal services. Leave it `true` only if you trust every workspace owner and relay through a local mail server.

Optional settings:

- `AUTH_REMEMBER_MINUTES`: how long "remember me" lasts. The default is 43200 (30 days).
- `INERTIA_ENCRYPT_HISTORY`: on by default, so back-button pages can't show data after logout.
- `INERTIA_DEVTOOLS_ENABLED`: off by default. Never enable it on a public install, because it serves recorded request data over HTTP.

## HTTPS and reverse proxies

Terminate TLS in front of the app and set `APP_URL` to the `https://` address. Session cookies are marked Secure by default and won't be sent over plain HTTP. Responses carry HSTS whenever the request arrives over HTTPS.

If the app runs behind a proxy or load balancer, configure trusted proxies in `bootstrap/app.php`:

```php
->withMiddleware(function (Middleware $middleware): void {
    $middleware->trustProxies(at: ['10.0.0.0/8']); // your proxy's addresses
    // ...
})
```

Without trusted proxies, Laravel sees every request as HTTP and from the proxy's IP address. That breaks rate limits, which then apply to everyone at once, as well as session IP records and HSTS.

## Workers and scheduler

Run one or more queue workers under a process manager. A Supervisor example:

```ini
[program:nudge-worker]
command=php /var/www/nudge/artisan queue:work --tries=3 --timeout=3600
directory=/var/www/nudge
user=www-data
numprocs=2
autostart=true
autorestart=true
stopwaitsecs=3660
redirect_stderr=true
stdout_logfile=/var/www/nudge/storage/logs/worker.log
```

Sending, automations and imports use the `default` queue unless you set `MARKETING_SENDING_QUEUE` or `MARKETING_IMPORTS_QUEUE`. If you do set them, pass the queue names to `queue:work --queue=...`.

The scheduler starts scheduled campaigns and recovers stuck work. Add this cron line:

```cron
* * * * * cd /var/www/nudge && php artisan schedule:run >> /dev/null 2>&1
```

## Sending setup

- **DNS:** publish SPF, DKIM and DMARC records for every From domain you send from, following your provider's instructions. Without them, mail lands in spam or is rejected.
- **Webhooks:** each provider's settings page in the app shows the webhook URL (`/webhooks/providers/{token}`). Register it with the provider so bounces and complaints are tracked. That tracking is what suppresses bad addresses and auto-pauses a workspace whose bounce or complaint rate gets too high.
- **Signing keys:** for providers that sign their webhooks, paste the provider's signing key into the provider settings. Webhooks are refused until it's set.
- **Amazon SES:** deliver events through SNS. The first signed message pins the SNS topic, and messages from any other topic are refused afterwards. Saving the provider again resets the pin.

## API docs

Every install serves a reference for its own API at `{APP_URL}/api/v1/docs`, and the raw OpenAPI spec at `{APP_URL}/api/v1/openapi.json`. The spec names your install's own base URL, so it can be imported straight into Postman, Insomnia or Bruno. Neither address needs an API token, because they describe open-source code and hold no data.

Set `MARKETING_API_DOCS=false` to turn both off. The docs page loads its viewer from a CDN (jsDelivr), so the reader's browser needs internet access; the spec itself is served from your own app.

## Keys

Keep `APP_KEY` secret and backed up. It encrypts sessions and stored provider credentials, and it signs tracking and unsubscribe links.

## Rotating APP_KEY

Rotate the key if it may have leaked:

1. Copy the current `APP_KEY` value into `APP_PREVIOUS_KEYS`. Separate several old keys with commas.
2. Run `php artisan key:generate` to set a new `APP_KEY`.
3. Run `php artisan config:cache` and `php artisan queue:restart`.

New links are signed with the new key. Unsubscribe, click and open links in emails already sent keep working as long as the old key stays in `APP_PREVIOUS_KEYS`, and so do stored credentials. Keep it there for as long as old emails might still be acted on; a year is sensible for unsubscribe links. Signed-in users stay signed in.

## Upgrading

```sh
git pull
composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
php artisan queue:restart
```

`queue:restart` makes workers finish their current job and reload the new code. Read the release notes for new environment values before upgrading.
